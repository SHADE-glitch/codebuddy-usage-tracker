# cbut — read-only audit report (2026-10-26)

> **A snapshot, not current state.** One-off read-only audit of
> `codebuddy-usage-tracker` at `ae9032e`, taken on 2026-10-26: source reading, independent
> SQLite probes on copies under `/tmp`, and a full test run. Nothing was installed, nothing was
> built, and no file in the repository was modified during the audit. Every item below that was
> repaired afterwards carries **fixed in `<commit>`**; the rest stay **open** and are listed at the
> end. Do not copy the counts in this document — run the suite and read the board.

- **Baseline**: `python3 -m unittest discover -s scripts/tests` → **572 tests, OK** (304 s) at
  audit time. 553 was a historical number from the CHANGELOG, not a current claim; the READMEs
  already said 572 and both matched the run.
- **Method**: full read of `scripts/`, probe scripts against copies of a live database, and a
  fresh `--full` build under `/tmp`.
- **Verdict**: the read-only design, the parameterised SQL and the incremental/idempotent sync all
  hold. The failures cluster in one place — **what happens when a source file disappears or a
  column is unknown** — plus four display surfaces that report a page as if it were a total.

## 1. Findings

| # | Severity | Finding | Status |
|---|---|---|---|
| 1 | P1 | An in-place transcript rewrite triggers a pre-pass that deletes `sessions` with no snapshot; sessions whose source CodeBuddy already pruned are never rebuilt, leaving orphan `tool_calls`/`model_responses` | fixed in `226a0d6` |
| 2 | P1 | `plugin_usage`'s unique key contains nullable columns, so `INSERT OR IGNORE` never dedups a NULL `session_id` or `ts`; every sync added another row | fixed in `bc8a4af` |
| 3 | P2 | `sessions.started_at`/`ended_at` latch to NULL forever once a scalar `MIN`/`MAX` sees NULL; the session then appears in no window at all | fixed in `0cace82` |
| 4 | P2 | `sessions.tokens`/`duration_ms` store "not reported" as a real 0 (905 of 1025 sessions) | fixed in `0a201b2` |
| 5 | P2 | Usage filter reports the page size as the match count, and its `LIKE` does not escape `%`/`_` | fixed in `f8c0eb2` |
| 6 | P2 | `cbut stats` prints a bare table header for an empty Top tools / Plugins section | fixed in `2987a4e` |
| 7 | P2 | MCP drill-down filters by tool name only, so two servers exposing the same tool are merged under one title | fixed in `2b7cd8b` |
| 8 | P2 | The single-response detail prints the storage sentinel `builtin` instead of the provider label | fixed in `59bc96c` |
| 9 | P2 | `--full` silently drops history whose source files are gone; the README said only "rebuild from scratch" | fixed in `49f0d32` |

The repairs are recorded as **D-065…D-072** (`79320b8`). Schema went to v13 (`b718d83`).

### Evidence for the two P1s

1. **Pruned sources.** Forcing a stale offset on a copy of the live database re-read 4,626 files
   and took sessions from 1,025 to 910, leaving 9,379 orphan `tool_calls` and 6,210 orphan
   `model_responses` behind: 115 sessions and 5,394 attributed calls lost, with no snapshot to
   roll back to. The fix snapshots first, carries the old session rows through the rebuild, and
   prunes the calls that can no longer be listed anywhere.
2. **Nullable unique key.** One `agent_usage` row with `session_id IS NULL` — the normal shape for
   an OTel agent span, 10,374 of which exist in the live database — gained a `plugin_usage` row on
   every backfill: 0 → 1 → 2 → 3 over three runs, and the systemd timer runs every 15 minutes.

## 2. Verified clean

These were checked and held, not merely not-looked-at:

- **Concurrency**: `run()` takes the `<db>.lock` sidecar for the whole run; a missing `fcntl`
  degrades to unlocked rather than corrupting.
- **SQL**: every value is bound; the only identifiers are literals in `cbut_db.py`.
- **Test isolation**: each suite builds its own database under a temp root; no suite reads
  `~/.codebuddy`.
- **Documentation as a claim**: the README's per-file test table matched the run line by line; the
  CI matrix (3.11 + 3.14) matched `docs/maintenance/compatibility.md`; every `D-###` referenced by
  `AGENTS.md` is defined; `bin/cbut`'s help is generated from its own comment block.
- **Privacy**: only structured metadata is read; no content column is stored.

## 3. Standards deviations found (all fixed)

1. Both READMEs still called OTel trace ingestion "planned, not yet wired", while the same files
   listed it as a source and the live database held 11,049 `source='span'` rows.
2. Both READMEs' `cbut-stats.py` subcommand list omitted `vacuum`; a guard now derives the list
   from argparse.
3. `_MODEL_ALWAYS_KEEP` is 7 while its docstring said five columns.
4. `AGENTS.md`'s "incremental and idempotent" paragraph did not describe the automatic rebuild
   path; it now does.

`docs/reports/STATE.md` is a handover draft frozen at 2026-10-11 and 334 tests. It is left
untouched by design — read it as history, never as current state.

## 4. Open after this round

- `ux_commands` has the same nullable-key shape as `plugin_usage` did; no NULL row exists on this
  machine, so there is nothing to measure.
- `cbut show mcp <tool>` (headless) still filters by tool only; the CLI has no `--server`.
- The prune rule deliberately spares rows whose `project` is NULL: 104 `autoModeClassifier` spans
  carry a `session_id` but no project, so the Agents total still exceeds the session-side count.
  Widening the rule would delete every call on a machine whose transcripts carry no cwd.
- Historical orphans are only cleared by the next rebuild; a migration cannot tell which rows were
  already lost.
- Unverified suspicions worth a second look: a partial `rawUsage` re-report could overwrite a good
  token value with NULL; a file rewritten *larger* with a newline still at `offset-1` would resume
  mid-file; `function_call` records without a `callId` land on a NULL primary key and can never be
  updated by their result.
